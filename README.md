# 五端口虚拟交换机实验台（多组共用）

Flask 实现的 5 端口 VLAN 感知学习型交换机，支持实训室多组学员共用一个服务：
每组在网页上开自己的练习台，组员用同一链接进入，台间状态完全独立，
空闲自动回收名额。

## 功能

### 多实验台管理（本次新增）

- 网页「新开练习台」开台，每台从**空白五端口交换机**开始；组员用同一个
  `/bench/<token>` 链接进入同一台
- 每台独立维护 VLAN、MAC 表、积压与事件日志；**复位只作用于本台**，
  其他组的台不受影响
- 最多同时 **3 台**；满额再开返回 `409` 并提示「实验台已满」，
  首页按钮同步置灰
- **空闲回收**：开台或上一次写操作成功结束后，空闲满 5 分钟即回收
  （`BENCH_IDLE_TIMEOUT` 可调）。GET 页面/状态只查看、**不续期**；
  页面自动刷新不会让台续命
- **在途写保护**：已受理的写操作结束前，即使空闲到期也不回收该台，
  该台仍可正常使用并继续占名额；写操作成功结束后才刷新空闲计时，
  下一轮回收周期才处理
- 台间各自一把锁：一台放行积压（或任何写操作）时，其他台仍能正常发帧
- 名额腾出后即可另开新台；已回收台的旧链接与补发请求一律返回
  **410「已被回收」**（未知链接返回 404），墓碑机制保证旧 token
  永远不会解析到之后新开的台
- 首页展示在役台、进入链接、已空闲时间与回收倒计时；台内页面也显示
  回收倒计时，被回收后出现红色横幅并禁用全部操作

### 单台交换机能力（原有）

- 网页改配任意端口 VLAN（1–4094）
- 发送带源/目的 MAC 的单播帧（非法 MAC、非单播目的会被拒绝）
- 每端口独立「暂停出帧 / 放行出帧」：暂停期间发往该口的帧进入积压队列，
  放行时按 FIFO 全部交付
- 各 VLAN 独立学习源 MAC；已知目的按表转发，未知目的只泛洪到本 VLAN 其他端口
- 带积压改配：改配生效瞬间，指向该口的学习项（跨所有 VLAN）与该口待发队列
  同时失效；切回原 VLAN 也按空队列处理；其他端口积压照常交付

## 启动

### Docker Compose（推荐）

```bash
docker compose up --build
# 打开 http://localhost:8000
```

### 本地直接运行

```bash
pip install -r requirements.txt
python app.py          # http://localhost:8000
```

### 环境变量

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `BENCH_MAX` | `3` | 同时在役实验台数量上限 |
| `BENCH_IDLE_TIMEOUT` | `300` | 空闲回收时间（秒），开台或上次成功写后起算 |
| `BENCH_REAP_INTERVAL` | `10` | 后台回收线程轮询间隔（秒）；另有访问时惰性回收兜底 |

冒烟/验收想快速看到期回收时，可临时设 `BENCH_IDLE_TIMEOUT=2`。

## HTTP API

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 首页：开台、名额与在役台清单 |
| GET | `/bench/<token>` | 某台的控制台页面（回收后 410、未知 404） |
| GET | `/api/benches` | 名额概况与在役台清单 |
| POST | `/api/benches` | 新开练习台（满额返回 409） |
| GET | `/api/bench/<token>/state` | 本台全部状态（只读，不续期） |
| POST | `/api/bench/<token>/frame` | 发帧 `{port, src, dst, payload}` |
| POST | `/api/bench/<token>/port/<id>/vlan` | 改配 VLAN `{vlan}` |
| POST | `/api/bench/<token>/port/<id>/pause` | 暂停出帧 |
| POST | `/api/bench/<token>/port/<id>/release` | 放行出帧（交付积压） |
| POST | `/api/bench/<token>/reset` | 复位本台（不影响其他台） |

错误约定：业务输入错误 `400 {"error": ...}`；台已回收
`410 {"error": ..., "reclaimed": true}`；未知 token `404`；满额开台 `409`。

## 设计要点

- `bench.py` 的 `BenchManager` 用一把锁保护注册表/名额/墓碑；每个 `Bench`
  自带独立 `RLock` 串行化本台写操作，不同台的写互不阻塞。
- 写流程固定为 `begin_write`（inflight+1，不续期、不触发回收）→ 本台锁内执行
  → `end_write`（成功才刷新 `last_write`）。因此失败/被拒的写不会续命，
  在途写期间回收器跳过该台，写结束后才重新计时。
- 回收双保险：后台线程每 `BENCH_REAP_INTERVAL` 秒扫一次；每次读访问/开台时
  再做一次惰性回收，避免休眠精度问题导致台迟迟不释放。
- 已回收 token 进入墓碑队列（上限 200 条），旧链接/补发请求稳定得到 410，
  不会与之后新台的 token 混淆（token 为 `uuid4` 随机串）。
- `switch.py` 为纯模型：`set_vlan` 在同一临界区内依次改端口 VLAN、
  删除跨 VLAN 的相关学习项、清空本口积压，三者对观察者原子。
- 不变式（`Switch.check_invariants`，测试与冒烟均断言）：
  学习项必指向当前处于该 VLAN 的端口；有积压的端口必处于暂停态；
  积压帧的 VLAN 必等于端口当前 VLAN。

## 测试

```bash
python -m unittest discover -s tests -v   # 34 个单元测试（模型/台管理/HTTP API）
python scripts/smoke_http.py              # 真实 HTTP 服务端到端，31 项检查
```

冒烟脚本把空闲超时压到 2 秒，自动覆盖：两组并行与跨台不阻塞、满额 409、
到期回收（只读不续期/写续期/旧链接 410/名额腾出再开）、在途写保护、
单台转发回归。

## 已知限制 / 余项

- 使用 Flask 内置开发服务器（threaded），未接 gunicorn 等生产级 WSGI；
  台状态存内存，进程重启即丢；无认证，仅限可信实验室网络使用
- 只支持单播帧（广播/组播目的被拒绝）；无 STP、无端口镜像
- 积压队列无长度上限；每端口已收帧历史保留最近 500 条
- 墓碑最多保留最近 200 个已回收 token（超出后最旧的 410 会退化为 404，
  均为拒绝操作、不会误命中新台）
- 本环境未安装 Docker，`docker compose up --build` 未在本机实跑；
  已通过 YAML 校验、Dockerfile 路径核对及同代码本地等价运行验证
